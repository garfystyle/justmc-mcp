# Старт: как писать код JustMC на Xero

Прочитай один раз за сессию. Темы подробнее: `guide` без аргументов.

## Порядок работы

1. Пойми, что должно произойти в игре, и каким шагом это можно доказать.
2. `guide` по теме задачи. Нужен приём — `examples`, нужно имя — `find`. Имена не угадывать: их больше тысячи, и похожие часто значат разное.
3. Напиши код. `check`, пока нет ошибок и предупреждений без объяснимой причины.
4. `test` со сценарием, который доказывает поведение. Падает — читай ошибку сервера, правь, повторяй.
5. Сдавай только то, что прошло `test`. В ответе скажи, что проверено сценарием, а что нет.

`test` сам заливает код и заменяет прошлую заливку этого проекта, остальные строки мира не трогает. Новая фича рядом со старой — отдельный `project`, иначе прошлая заливка сотрётся: `attention` в отчёте об этом скажет. Одноимённую чужую функцию заливка заменять откажется: переименуй свою или подтверди `drop`. Копия мира перед изменением лежит в `~/.justmc-mcp/backups`.

Код мира читается из файла, который пишет заливка. В новом мире файла нет: `world` действие `adopt`, без `path` для пустого мира, с `path` на json с `handlers`, если код там уже есть.

## Скелет

```kotlin
const PREFIX = "&6[Игра] &f"
const SWORD = item(diamond_sword, name: "&bМеч героя", tags: {kind: "hero"})

save `монеты %player%`
game round

func reward(amount: number = 10) {
    `монеты %player%` += amount
    send_message("${PREFIX}Монет: ${`монеты %player%`}")
}

process tick() {
    forever {
        wait(1s)
        round += 1
    }
}

when world_start {
    start tick()
}

when player_join {
    give_items(SWORD)
    reward()
}

when player_chat {
    if chat_message_equals("@bal") {
        cancel_event()
        send_message("${PREFIX}Монет: ${`монеты %player%`}")
    }
}
```

## Что откуда

Код живёт только в `when`, `func`, `process`. Снаружи — `const`, `import`, объявления `game x`, `save x`.

Чаще всего в модулях: `player_join`, `player_chat`, `player_right_click`, `world_start`, `player_click_inventory`, `player_quit`, `player_left_click`, `player_break_block`, `player_death`, `player_move`, `player_take_damage`.

Значения: `value.location`, `value.event_chat_message`, `value.name`, `value.eye_location`, `value.target_block_location`, `value.main_hand_item`, `value.uuid`, `value.open_inventory_title`, `value.event_item`, `value.event_slot`, `value.timestamp`.

Цели ставятся перед действием, условием или значением. В событии с двумя участниками цель решает всё: `@killer`, `@victim`, `@damager`, `@shooter`. Массово: `@all`. Только что созданная сущность: `@last`.

## Переменные

| Запись | Живёт |
|:--|:--|
| `x = 1` | одно срабатывание, видна вызванным функциям |
| `line x = 1` | свой обработчик и один вызов: у другого `func` или `process` это другая переменная |
| `game x` | весь мир, пока он запущен |
| `save x` | весь мир, переживает перезапуск |

Состояние игрока почти всегда хранят в переменной с его ником в имени: `` game `hp %player%` ``. Так сделано в подавляющем большинстве модулей. Если данные должны пережить смену ника, вместо `%player%` пиши `%player_uuid%`.

Имя с пробелом или плейсхолдером — в обратных кавычках. Запись и чтение таких переменных работают как с обычными.

## Всем онлайн

Значение на каждого, включая `save` по нику: обход ников и обращение к переменной через `%var_local(ник)`.

```kotlin
save `монеты %player%`
save `монеты %var_local(nick)`

process income() {
    forever {
        wait(5s)
        all_players()
        for nick in value.selection_target_names {
            if var.exists(`монеты %var_local(nick)`) {
                `монеты %var_local(nick)` += 1
            }
        }
        reset()
    }
}

when world_start {
    start income(target_mode: no_target)
}
```

## Правила качества

Имена, состояния, размер функций и файлы: тема `style`. `check` проверяет их сам, код сдаётся без замечаний раздела «Читаемость».

- Повтор длинного значения — `const`. Повтор кода — `func`.
- Условие отказа — сразу наверх, с `end_thread()` или `return`, а не вложенность на пять уровней.
- Формула вместо цепочек `multiply`/`add`: она собирается в один блок.
- Событие, которое ты обрабатываешь сам, отменяй первой строкой: `cancel_event()`. Иначе сообщение уйдёт в чат, предмет выпадет.
- Свои предметы отличай тегом, а не именем: имя видно и меняется, тег нет.
- Проверяй существование данных при входе: `if not var.exists(...)`, иначе первая операция прочитает пустоту.
- Текст игроку — короткий и единый по стилю, префикс в `const`.
- Одно длинное ожидание лучше частого опроса. `player_move` срабатывает очень часто: тяжёлую работу в него не ставить.

## Ловушки сервера

Проверено на сервере:

- `/dev` → `/play` не перезапускает мир: `world_start` не срабатывает, старые процессы живут. Перезапуск — `/build`, потом `/play`. `test` делает это сам после заливки, а игроку об этом надо сказать.
- `[a, 2]` и `{"k": a}` с переменной внутри собираются блоком создания и работают. Значение как есть, без подстановки, — `literal([a, 2])`, в обычном коде оно не нужно.
- Формулу и текст с плейсхолдером в аргументе компилятор считает до вызова сам: `f(n - 1)`, `start p("t${x}")`. Рекурсия работает. В коде из мира такой аргумент виден как `literal(x + 1)`: сервер получает его несчитанным.
- Список и словарь в аргументе передаются по ссылке: правка внутри функции видна снаружи. `k = l` — копия.
- `line x` своя у каждой строки. Локальная `x` общая у функции и вызывающего кода: запись внутри функции меняет `x` снаружи, компилятор предупреждает.
- Вид переменной, которую задаёт другой код, объявляй сразу: `save m: map`, `game l: list`. Тогда работают `m[k] = 1` и `k in m`.
- Параметр функции: `amount: number "Сколько выдать" = 1`. Описание видно в сундуке вызова. `lines: text[3]` принимает до трёх значений, в вызове — списком.
- Локальные переменные функции общие с вызывающим кодом: `n = 0`, вызов функции с `n = 5` внутри, и снаружи уже 5. Даже счётчик цикла `for i, n in l` затирает внешние `i` и `n`. В функциях бери свои имена или `line x`.
- В режиме игры игрок в приключении: ломать блоки нельзя, пока код не сделает `set_gamemode(gamemode: survival)` или `creative`.
- `value.timestamp` идёт с точностью до секунды: кулдаун короче секунды на нём не считается. Точное время — `value.server_current_tick`, 20 в секунду.
- `x += 1` создаёт незаданную переменную. Цикл, начисляющий всем, ломает проверку первого входа `if not var.exists(...)`: начисляй только тем, у кого переменная уже есть.
- В событии мира (`world_start`, `time_skip`) игрока по умолчанию нет. `send_message("x")` никому не дойдёт, нужен `@all`.
- Незаданная переменная внутри формулы обнуляет всё выражение: `x = x + 10` с пустой `x` даёт 0, а `x += 10` даёт 10.
- Локальная переменная не доживает до следующего события.
- Индексы списков с нуля, конец диапазона `1..5` включается.
- Текст `"abc"` в числовом аргументе останавливает строку ошибкой, текст `"5"` работает.
- Ошибка останавливает только это срабатывание строки: следующие срабатывания и другие события работают.
- Вызов функции с другим набором параметров сервер отвергает: «Функция с такими параметрами не найдена».

Имена, которые есть в нескольких категориях, пишутся с категорией: `player.teleport`, `entity.teleport`, `var.exists`, `entity.remove`.

## Сценарий test

Шаги идут по порядку от лица настоящего игрока. Проверка должна падать, если поведения нет.

```json
[
  {"say": "@shop"},
  {"gui": "Магазин"},
  {"click": 2},
  {"expect": "Куплено"},
  {"item": "emerald", "count": 2}
]
```

- `expect` ждёт новую строку чата после предыдущего `expect`, `absent` смотрит весь прогон.
- Ошибки сервера (`❌`, `☠`, «остановило строку кода») валят тест сами, ожидаемые снимает `tolerate`.
- После заливки мир перезапускается: срабатывают `world_start` и `player_join`, поэтому сообщение при входе проверяется первым шагом.
- Блоки и мобы на карте переживают прогоны и перезапуск мира. Убирай за собой: забытый камень душил мобов следующего сценария, а старый моб принимал удар на себя.
- Значение `game` и `save` читай шагом `var`: это настоящее значение из мира. Локальную покажи в чат (`send_message("x=${x}")`) и проверь `expect`.
- Первый вход проверяй так: тестовая команда стирает переменную (`var.remove`), затем второй `test` без кода и с `restart: true`.
- Тестовые команды держи в файлах `*.debug.xero` папки проекта: их заливает `test`, а `deploy` нет. В обычный код они не попадают.
- Шаг `screenshot: true` приложит снимок, при провале снимок приложится сам.
- Для того, чего в чате нет, годится `java` с выражением в клиенте: `mc.player.getHealth()`.
