# Сервер JustMC Creative+ как среда

Откуда факт: **[Л]** локализация сервера, **[В]** вики `justwiki.gitbook.io/wiki`, **[Ч]** чат игроков (слух). Без пометки: проба на сервере. Спор решает проба.

## Режимы мира

У мира два состояния: строительство и игра [В]. `/dev` не состояние, а отдельное измерение, куда уходит игрок.

| Команда | Ответ | Что происходит |
|:--|:--|:--|
| `/build` | `Мир запущен в режиме строительства` | код выключен, творческий режим. Если мир уже в строительстве, молчит: жди состояние игрока |
| `/play` | `Мир запущен в режиме игры` | код включён, игрок в приключении |
| `/dev` | `Вы перешли в режим изменения кода мира` | мир не меняется: режим игры работает дальше |

| Переход | `world_start` | `game` | Процессы |
|:--|:--|:--|:--|
| `/build`, пауза, `/play` | да, и `player_join` | очищены | убиты |
| `/dev`, потом `/play` | **нет**, хотя ответ тот же | прежние | живы |
| `/play` в режиме игры | нет, идёт `player_rejoin` | прежние | живы |
| `/module load-url` в работающий мир | нет | прежние | живы, крутят старый код |

- **Перезапуск мира** один: `/build`, дождаться перехода, пауза ~1,5 с, `/play`. Без паузы второй ответят `Подождите…`, и мир останется в строительстве.
- `/play` доступен любому игроку и возвращает его к началу. Запретить: `cancel_event()` в `player_rejoin` [Ч].
- `world_stop` срабатывает при остановке режима игры [Л]. Успевает ли он при падении сервера, неизвестно: важное пиши в `save` сразу.

Перезапуск переживают `save`, код, блоки и мобы на карте (убирай сам). Не переживают `game` и функциональные блоки на этажах редактора [В].

**Заморозка.** После критической ошибки мир замирает: `Ожидайте конца остановки мира!` [Л]. Длительность в `value.delay_reload_count`, начало в `value.start_reload_tick`, конец даёт `world_reload` «Мир разморозился». В 1075 модулях его нет ни разу. Живы ли потом `game` и процессы, не снято, циклы запускай заново. Худший случай, `world_fatal_exception`: `…выполнения кода было полностью остановлено. Для возобновления работы пропишите /build и /play`.

```kotlin
process tick() {
    forever { wait(1s) }
}
when world_start {
    start tick(target_mode: no_target)
}
when world_reload {
    @all send_message("&eМир разморожен")
    start tick(target_mode: no_target)
}
```

**Рестарт сервера** ежедневный, с отсчётом `Ежедневный рестарт через 5 мин!`, затем `Вы были кикнуты с сервера cr-1: Restart server`. `Timed out`: чат обрывается, через 30 с клиент отключается, это сервер. Сам не переподключайся.

Настройка «Выключение мира при выходе игроков» [Л]; опубликованный мир запускает любой игрок, даже без автора [В].

## Лимиты

`/world limit profile` показывает настоящие счётчики мира (снято 04.11.2026, ранг Moon):

| Счётчик | Предел | Смысл |
|:--|:--|:--|
| `blockChangesCount` | 200 000 | изменённых блоков **за тик**, превышение останавливает код мира (`Изменено слишком много блоков`) |
| `editSessionCount` | 100, мягкий 25 | сессий правки блоков. У мягкого предела `set_block` по одному упирается примерно в 15 за тик и молча ждёт, без ошибки |
| `waitActionCounter` | 3 000 | активных `wait` |
| `asyncCounter` | 1 000 | асинхронных задач |
| `getSkinCounter` | 100 | загрузок скинов |
| `reportShowCounter` | 100 | показов ошибок |
| `particleCallLimit` | 30 000 | вызовов частиц |
| `tick20Mspt` | плавает, чаще 4 мс | среднее время тика мира за 20 тиков. Знаменатель в отчёте менялся от 4.00 до 7.14 мс, постоянным его не считай |
| `msptMin` | 4 мс | порог, от которого считаются скачки |
| `boostMsptCounter`, `superBoostMsptCounter` | 40, 20 | счётчики скачков нагрузки: `high_cpu_boost` |
| `contextLifeTime` | 300 мс, шаг 25 мс | сколько живёт один запуск кода без `wait` |

**Сколько можно.** 100% `value.cpu_usage` это примерно 4 мс на тик: при `tick20Mspt 0.80/4.00` код получил 18 (проба 07.11.2026). Первая версия физики при оценке «уложимся в 6.25 мс» дала пик 182% и `high_cpu_boost`, потому что считать надо от 4 мс.

**Поле `CPU:` в отчёте не про твой мир.** В пустом мире при `tick20Mspt 0.02` оно показало 969%, при 0.80 показало 683%, значения прыгали от 300 до 1100 без связи с кодом. Смотри `tick20Mspt`, `boostMsptCounter`, `value.cpu_usage` и панель `/world limit bar`.

**Цена действий**, `measure_time(..., duration: microseconds)` на сервере, по 300 повторов (05.11.2026):

| Действие | мкс |
|:--|--:|
| пустой `repeat` | 0.44 |
| формула: база и слагаемое | 1.4 и 0.75 на слагаемое |
| `x += 1` | 1.9 |
| чтение и запись списка | 1.5, 1.3 |
| `if` | 1.1 |
| вызов функции без значения | 2 |
| функция с параметром и `return` | 5–8 |
| действия с вектором | 1.5–2.3 |
| выбор сущности по UUID | 2 |
| выборка по тегу на 54 сущности | 143 |
| `set_rotation` на 54 сущности | 127 |
| `set_display_translation`, интерполяция | 4, 2.7 |
| `set_display_correct_transformation_matrix` | 32 |
| `entity.teleport` | 6.5 |

Эта таблица занизила настоящую физику в 6 раз: дают параметры функций и вызовы во вложенных циклах. Поэтому бюджет считает `measure_time` вокруг настоящего куска работы, а не сумма цен. Правку блоков стоит вызов, а не блок: `set_region` на 65 и на 16 640 блоков стоит одинаково, 10 вызовов за тик это предел, 30 дают `high_cpu_boost`.

**Сервер общий.** На одном инстансе живут десятки чужих миров, отвечает за нагрузку аккаунт пользователя, а лимиты мира соседей не защищают. Не доводи мир до отказа ради замера и не гоняй перезапуски подряд. Замеряй малым прогоном при `value.cpu_usage` ниже 50, предел ищи расчётом. Просьба остановиться в чате мира или жалобы на заморозку значат стоп и сообщение пользователю. После `☠` не запускай следующий прогон, пока не понятна причина.

|:--|:--|:--|
| Этажи, строки | 15 этажей. Мир 06.11.2026 упёрся в 345 строк (23 на этаже). С 07.11.2026 этаж 144×144: 35 строк, по расчёту 525, старые миры не перемерены | `Нельзя добавить больше этажей`, `Не хватает места…` |

| Кастомных рецептов 128, длина текста 25 000 | | [Ч] |

| Частота | Предел | Ответ |
|:--|:--|:--|
| Команды, чат | ~1,5 с | `Подождите перед повторной отправкой сообщения` |
| Шаблон строки | ~1 с, после установки ~2 с | `Подождите перед сохранением шаблона` |

**Числа нет нигде, не называй его:** действий и итераций за тик, процессов, веб-запросов, карт, кастомных тегов, сохранений инвентаря, обновлений таба. Предел есть, ответит ошибкой. **Сообщения нет вовсе:** сущности в мире, скорборды, босс-бары. 1200 визуализаторов созданы без отказа (`displays`).

Нагрузка из кода: `value.cpu_usage` (59 модулей, порог 70–85), `value.server_tps`, `value.particle_cpu_usage`. Порог не спасает от скачков: при проверке «≤ 10%» с шагом 5 тиков всё равно шёл `high_cpu_boost` [Ч]. Лечит ровный размер порции (`loops-ui`, «Большая работа порциями»). `measure_time` считает и `wait` [Л].

## Ошибки выполнения

`Действие Телепортация остановило строку кода из-за ошибки:`, затем текст. Нажатие переносит к блоку.

| Уровень | Заголовок | Итог |
|:--|:--|:--|
| `⚠ Предупреждение` | `Действие {0} вызвало предупреждение:` | строка идёт дальше |
| `❌ Ошибка` | `Действие {0} остановило строку кода из-за ошибки:` | остановлено это срабатывание, остальное работает |
| `☠ Критическая ошибка` | `Выполнение кода было остановлено из-за ошибки:` | встал весь код мира |

Уровни ошибок локализация не пишет. Видели: ⚠ `Данное событие нельзя отменить`; ❌ `expected_but_got`, `index_out_of_bounds`, `function_with_parameters_not_found`, `fromIndex…`; ☠ `high_cpu_boost` [Ч].

| Сообщение (id) | Значит → чинить |
|:--|:--|
| `Цикл выполнил слишком много итераций за один тик`, `Обнаружен бесконечный цикл без задержки` (`repeat_timeout`) | цикл без паузы → `wait` по счётчику |
| `Выполнено слишком много действий за один тик` | весь мир → разнести по тикам |
| `Выполнение действия заняло слишком много времени` (`tick`, `second`, `line`, `timeout_cancellation_process`), `Действие выполнялось слишком долго` (`line_lifetime`) | бюджет, большой список → порции |
| `Строчка события выполнялась слишком долго!` (`timeout_event`) | у события свой предел → тяжёлое в `start` |
| `…превысило в два раза доступный лимит… Ожидайте конца остановки мира!` (`life_time`) | заморозка → ждать `world_reload` |
| `Высокое использование процессора` (`high_cpu`, `max_tick`, `super_high_cpu`), `Слишком частые скачки нагрузки` (`high_cpu_boost`) | → `value.cpu_usage`, ровные порции |
| `Бесконечная рекурсия` (`sync_run`), `Превышена максимальная глубина вложенных вызовов` | самовызов → цикл с `wait`, условие выхода |
| `События вызвали друг друга слишком много раз` (`trigger_overflow`) | урон в событии урона → флаг |
| `Запущено слишком много процессов`, `…асинхронных задач` | `start` в частом событии → один цикл мира |
| `Превышен лимит количества действий "Ждать" за тик`, `…активных действий "Ждать"` | `wait` в `player_move` → один цикл |
| `Изменено слишком много блоков` | → порции с `wait` |
| `Ожидал аргумент "{0}" с типом {1}, но получил {2}` (`expected_but_got`) | не тот вид; текст `"5"` в числе работает, `"abc"` нет |
| `Необходим аргумент "{0}" с типом "{1}"` | пустой обязательный. В июле пустое место у моба прошло молча, без ошибки |
| `Индекс {0} выходит за границы списка` | индекс с нуля, или список не передан |
| `Значение не является целым числом` (`not_a_number`) | → `exception` |
| `Функция с такими параметрами не найдена`, `Функция с именем {0} не найдена`, `Процесс с именем…` | другой набор или имя из переменной, бывает при `call(…)` |
| `Список пуст`, `Предмет не найден`, `Тег не найден`, `Некорректное регулярное выражение`, `Указан невалидный HEX-цвет`, `Путь NBT не найден` | проверяй данные перед действием |
| `Возникла непредвиденная ошибка`, сырой текст Java | баг сервера → обойти другим действием |
| `Данное событие нельзя отменить` (⚠) | отменяемые помечены в `events.md` |
| `Данное событие не имеет урона…` и подобные | `set_event_*` не там |
| `Нельзя удалить сущность в событиях Создания и Удаления`, `…Укажите задержку` | сначала `wait` |
| `Действие не может быть вызвано в событии "Игрок вышел из мира"`, `Невозможно нанести урон вышедшему игроку` | игрока уже нет |
| `Сущность {0} не найдена`, `Сущность не является…`, `не может…`, `Блок не является…` | ~60 вариантов → проверь тип |
| `Данное действие недоступно в этом мире` | закрыто, см. ранги |
| `Достигнут лимит по количеству веб-запросов`, `Слишком частое обновление списка игроков`, `Слишком много загрузок скинов`, `…попыток сохранения инвентаря`, `…карт`, `…кастомных тегов` | реже вызывать, кэш в переменной |

**Ловить:** `exception` кладёт в переменную id ошибки (ключ локализации: `not_a_number`, `expected_but_got`, `function_not_found`), без ошибки в ней **число 0**, а не пустота: `err != ""` будет истинно всегда (проба 07.11.2026), сравнивай с id ошибки или с `0`. Глобальные и критические не ловит [Л], от нагрузки не спасает. Маркер `exception_type: enum("ALL")`, `"WARNING"`, `"ERROR"` уходит как есть.

```kotlin
when player_chat {
    if chat_message_equals("@num") {
        cancel_event()
        exception(err) {
            parsed = convert_text_to_number("abc")
        }
        if err == "not_a_number" {
            send_message("&cНужно число")
            end_thread()
        }
        send_message("n=${parsed}")
    }
    if chat_message_equals("@fail") {
        cancel_event()
        call_exception("no_money", "Не хватает монет", type: warning)
    }
}
```

**Молчит вовсе:** `%math` с незаданной переменной или битым выражением даёт 0; `send_message` без цели в событии мира; выборка не видит сущности в незагруженных чанках, поэтому и уборка их не снимет (`displays`).

**Выкидывает игрока:** `kick()`; античит (`Вы исключены из мира: сработал античит ({0})` или чёрный список, настройка в меню мира); отказ от обязательного ресурспака; `Cannot interact with self!`; предмет, который сервер не может закодировать (`EncoderException … container_set_slot`, в лобби); `SWAP`-клик по палитре /dev; отрицательный атрибут сопротивления воздуха [Ч]; `Restart server`; `Timed out`.

## Как выполняется код

- **Строка:** `when`, `func` или `process`. **Ветвь:** строка, вызванные функции и процессы с `share` [В]. `local` живёт в ветви, `line` в одной строке.
- Каждое срабатывание события выполняется отдельно: `wait` в частом событии плодит копии, а не очередь.
- **`wait`** держит только эту ветвь. 20 тиков в секунду; точное время `value.server_current_tick`, `value.timestamp` идёт шагом в секунду.
- **Функция** идёт в вызвавшей ветви: вызов ждёт её конца [В], локальные общие. `return` возвращает к блоку вызова, `end_thread()` останавливает и вызвавшую строку [Л]. Режима `line_variables_mode` [Л] в обычном вызове Xero нет.
- **Процесс:** своя строка, вызвавшая идёт дальше [В]; её `end_thread()` и ошибки на него не влияют. Значение не возвращает, снаружи не останавливается. Судя по `sync_run`, до первого `wait` он идёт сразу, порядок не снят.
- `start`: `local_variables_mode` бывает `dont_copy` свои, `copy` копия, `share` общие; `target_mode` бывает `current_target` цель события, `current_selection` текущая цель, `no_target`, `for_each_in_selection` процесс на каждую цель. В событии мира и `no_target` игрока нет, нужен `@all` или выборка.
- **Отмена** действует только на начальное событие [Л]: код строки идёт дальше, процессы и переменные не откатываются. Ставь первой строкой. После `wait` событие уже прошло: из 1719 обработчиков с отменой `wait` раньше стоит у 11, прямой пробы нет. `uncancel_event()` возвращает.
- **Отменены по умолчанию** [Л]: `player_skin_change`; `player_resurrect`, `entity_resurrect` без тотема; `player_ask_gamemode_change` без прав; `player_click_inventory`, `player_click_own_inventory`, `player_drag_inventory` в наблюдателе; `player_break_block` в творческом с мечом или трезубцем.
- **Порядок.** `player_respawn`: сначала `wait` [Л]. Порядок `world_start` и `player_join` не снят: циклы запускай в `world_start`, данные игрока проверяй в `player_join`.
- «Запуск в отдельном потоке» (`controller_async_run`) есть в локализации, в данных Xero и модулях его нет: внутри работают не все действия, отмена после него не работает [Л].
- Две функции с одним именем вызываются обе [Л]: так бывает после `load-url` без `force`.
